# SKILL：筛选交互实现与检查（filter-interaction）

> 一句话：这个 Skill 检查的是——一次筛选交互（关键词 和/或 分类维度如平台）是否把「有结果 / 无结果 / 清空恢复」三种界面状态都做完整，且可访问性达标。
> 版本：v2（Day 12 续 增补「平台/分类维度」与统一空态文案）｜ 适用：任何列表/榜单页新增筛选功能的实现前设计与实现后自检。

## 什么时候调用

给页面新增搜索框、下拉筛选、标签筛选、分类 chips 等"缩小结果集"的交互时，先读本文件再动手；写完后按第 3 节清单逐项复检。

## 1. 实现前必须先定的三态（缺一不算完成）

| 状态 | 必须做到 |
|---|---|
| ① 有结果 | 只显示匹配项；每栏/每处计数同步更新（如「3 条」）；用户能看出"是筛选后的结果" |
| ② 无结果 | 绝不显示空白页：**主文案固定用「没有找到相关内容」**，副文案说明当前条件（关键词/平台）并给出路（清除筛选按钮） |
| ③ 清空恢复 | 点清除按钮或删光关键词后，列表**逐条恢复原样**（顺序、条数、收藏标记都不变）；选择类筛选项一起复位；输入框重新聚焦 |

## 2. 实现检查清单（写代码时逐条对照）

**通用**
- [ ] 筛选只改"显示哪些行"，不改数据、不改收藏等其它功能（在渲染入口处过滤，别动数据源）
- [ ] 关键词匹配规则：标题包含即可，**不区分大小写**；关键词首尾空格要 trim
- [ ] 多个筛选维度之间是「同时满足」（AND），且必须能组合出无结果态
- [ ] 输入框有可见 `<label>`；placeholder 只做示例不做说明（DR-1：placeholder 不能当正式文案）
- [ ] 清除按钮：无任何筛选条件时禁用（不可点但看得见），有条件时可用；点击后**所有**维度复位且焦点回输入框
- [ ] 匹配计数放在输入框旁并带 `aria-live="polite"`；分母 = 当前维度范围的全量（如选了平台就只算该平台）
- [ ] 无结果文案里的关键词要转义后再插入（防 XSS，用项目里现成的 `esc()`）
- [ ] 输入框、按钮、chips 点击区高度 ≥40px（DR-7）；边框用 `--line-strong`（DR-2）；焦点有 2px 轮廓（DR-3）
- [ ] 页面四状态（加载中/成功/空/错误）不受筛选影响；详情弹层、收藏、抽屉回归正常

**分类维度（chips / 标签 / 下拉）**
- [ ] 选项由数据源或常量渲染（如按平台清单），不写死重复的 HTML
- [ ] 必须有一个「全部/不限」选项作为复位入口，默认选中
- [ ] 选中态用 `aria-pressed`（或 `aria-selected`）+ 视觉双通道（描边/底色/字重），不只靠颜色
- [ ] 只更新选中态时用属性同步，**不重建节点**（否则键盘焦点会丢）
- [ ] 切换维度后布局要收得住：单选某分类时只渲染该分类的区块，并保证不产生横向溢出（DR-10）
- [ ] 事件用委托绑定一次，避免重建后重复绑定

## 3. 实现后测试步骤（三态 + 回归，全部要实测）

1. **有结果（关键词）**：输入样本数据里存在的词（如「中秋」）→ 计数变「匹配 x/N 条」，各栏只留匹配行，栏头条数同步变小
2. **有结果（分类维度）**：点某个平台/分类 → 只显示该类内容，其余区块不渲染，计数分母变成该类总数
3. **组合有效**：分类 + 关键词同时生效（例：平台=微博、关键词=中秋 → 匹配 1/10 条）
4. **无结果**：不能只试关键词——**每个维度单独制造一次空、再组合制造一次空**；确认主文案是「没有找到相关内容」、副文案带当前条件、清除按钮可点
5. **清空恢复**：点「清除筛选」→ 行数、顺序、收藏标记与筛选前完全一致，chips 回「全部」，焦点回输入框
6. **回归**：不筛时页面与改动前一致；收藏/取消、详情弹层、`?state=` 四状态预览全部正常
7. **两档宽度**：360px 下 chips 换行不溢出、点选后仍不溢出不遮挡；桌面宽度下布局与改动前一致

## 4. 交付物

- 页面截图：**带地址栏**，能看到筛选关键词/选中的平台、匹配计数与筛选结果
- 调用记录：`skills/filter-interaction/CALL_LOG.md` 追加一条（何时、按哪节执行、结果）

## 边界

一天只建一个 Skill；本 Skill 不管筛选以外的功能（排序、收藏、接口请求等一律不动）。
