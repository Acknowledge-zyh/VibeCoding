# SKILL：筛选交互实现与检查（filter-interaction）

> 一句话：这个 Skill 检查的是——一次筛选交互是否把「有结果 / 无结果 / 清空恢复」三种界面状态都做完整，且可访问性达标。
> 版本：v1（Day 12 创建）｜ 适用：任何列表/榜单页新增筛选功能的实现前设计与实现后自检。

## 什么时候调用

给页面新增搜索框、下拉筛选、标签筛选等"缩小结果集"的交互时，先读本文件再动手；写完后按第 3 节清单逐项复检。

## 1. 实现前必须先定的三态（缺一不算完成）

| 状态 | 必须做到 |
|---|---|
| ① 有结果 | 只显示匹配项；每栏/每处计数同步更新（如「3 条」）；用户能看出"是筛选后的结果" |
| ② 无结果 | 绝不显示空白页：每栏给出「没有匹配“关键词”的结果」文案；提供一条明确的出路（清除筛选按钮） |
| ③ 清空恢复 | 点清除按钮或删光关键词后，列表**逐条恢复原样**（顺序、条数、收藏标记都不变）；输入框重新聚焦 |

## 2. 实现检查清单（写代码时逐条对照）

- [ ] 筛选只改"显示哪些行"，不改数据、不改收藏等其它功能（`renderBoard` 入口处过滤，别动数据源）
- [ ] 匹配规则：标题包含关键词即可，**不区分大小写**；关键词首尾空格要 trim
- [ ] 输入框有可见 `<label>`；placeholder 只做示例不做说明（DR-1：placeholder 不能当正式文案）
- [ ] 清除按钮：无关键词时禁用（不可点但看得见），有关键词时可用；点击后焦点回到输入框
- [ ] 匹配计数放在输入框旁并带 `aria-live="polite"`，筛选后读屏器能播报结果数
- [ ] 无结果文案里的关键词要转义后再插入（防 XSS，用项目里现成的 `esc()`）
- [ ] 输入框、按钮点击区高度 ≥40px（DR-7）；边框用 `--line-strong`（DR-2）；焦点有 2px 轮廓（DR-3）
- [ ] 页面四状态（加载中/成功/空/错误）不受筛选影响；详情弹层、收藏、抽屉回归正常

## 3. 实现后测试步骤（三态 + 回归，全部要实测）

1. **有结果**：输入样本数据里存在的词（如「中秋」）→ 计数变「匹配 x/30 条」，各栏只留匹配行，栏头条数同步变小
2. **无结果**：输入不存在的词（如「不存在xyz」）→ 各栏显示「没有匹配」文案而非空白，清除按钮可点
3. **清空恢复**：点「清除筛选」（或删光关键词）→ 行数、顺序、收藏标记与筛选前完全一致，焦点回输入框
4. **回归**：不筛时页面与改动前一致；收藏/取消、详情弹层、`?state=` 四状态预览全部正常

## 4. 交付物

- 页面截图：**带地址栏**，能看到筛选关键词、匹配计数与筛选结果
- 调用记录：`skills/filter-interaction/CALL_LOG.md` 追加一条（何时、按哪节执行、结果）

## 边界

一天只建一个 Skill；本 Skill 不管筛选以外的功能（排序、收藏、接口请求等一律不动）。
